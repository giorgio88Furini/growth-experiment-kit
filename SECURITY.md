# Security policy

## Supported versions

The current `1.x` release line is the supported line for security fixes. Use the latest release available from the project maintainer when releases are published.

## Reporting a vulnerability

Do not post credentials, personal data, or sensitive experiment records in a public issue. Report suspected vulnerabilities privately to the project maintainers through the repository's private vulnerability-reporting mechanism, if enabled. Include the affected version, reproduction steps, impact, and a minimal sanitized example. If private reporting is unavailable, contact the maintainers using the contact route listed in the repository hosting profile and request a private channel.

## Security scope

The CLI processes input values locally and makes no network requests. It does not persist data. Do not pass sensitive or regulated data unless your environment and handling procedures authorize it. This policy does not promise that statistical output is appropriate for a particular regulated, clinical, financial, or safety-critical decision.
